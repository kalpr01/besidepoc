FLOW A — Signed intent before network auth

At registration, the member chooses groceries or tickets and limits. At purchase time, the agent signs a payment intent. Occlet verifies the signature and any member approval before the separate Lithic authorization.

Agent signature → READY intent → Lithic ASA → exact card/merchant/amount match
FLOW B — Network authorization directly

The network delivers the virtual-card token, merchant and amount. Occlet infers the agent from the card's one-to-one registration, applies parent and delegated rules, and approves only within the auto-approval limit.

Lithic ASA → card-to-agent mapping → policy → funding. Attribution ≠ verified agent identity.
Flow A requires a signed pre-purchase intent; no approved intent means the later network authorization is declined.

L3 Local network-direct authorization (Flow B)

Use a CARD_BOUND_NETWORK delegated card from Steps 1–2. This request intentionally contains only card reference, merchant, amount and transaction reference. It does not transmit an agent identifier, key signature, or payment intent. The issuer resolves the registered agent from the card-to-delegation mapping.

Flow B approval is weaker evidence: owning the card credentials is not proof that the registered agent initiated the payment. Amounts above the auto-approval threshold decline; the network callback cannot await member approval.

L4 Optional: Capital One manual checkout handoff

Use Capital One reference only — no PAN, CVV, expiry, or Capital One login details. This is Occlet's pre-payment agent policy gate, not issuer authorization. You choose the checkout website; only its approved hostname can be opened through this path.

GROCERY_101 maps to target.com; ELECTRONICS_202 maps to bestbuy.com for this local proof of concept. The website does not attest to the final cart or merchant network ID.
